## 3. 文字绘制路径

**是 `Graphics.DrawString` + FontConfig。**

中间工厂：`ꢒ.ꞇ(Bitmap base, string text, int size, Color color, int x, int y, int offX, int offY, int W, int H, bool A_10, bool A_11, bool A_12, bool A_13)`（**ꢒ.cs:164**）。其内部：
- `font = new Font(_꧶.ꢒ, A_2, FontStyle.Bold)`（**ꢒ.cs:244**，全为粗体）
- `brush = new SolidBrush(A_3)`（**ꢒ.cs:486**，颜色=FontConfig.color）
- `graphics.DrawString(A_1, font, brush, A_4 + A_6, A_5 + A_7, stringFormat)`（**ꢒ.cs:340**，居中对齐）
- 输出裁剪后的字形位图返回。

`Graphics` 来自 LCD 显示缓冲：`Graphics.FromImage(ꪨ.ꭚ.갌())`（TItem.cs:932）或 `ꪨ.ꭚ.갌()`（TItem.cs:690）。

三条绘制分支：
- **逐字符缓存模式**（`isLongStr == false`）：`TItem.대()`（TItem.cs:560）。把 valueStr 拆成单字符 → 以 `key = 字 + x + posY + fontType.name + color.ToArgb()`（TItem.cs:836）查全局字典 `_꧶._A839`，命中直接 `DrawImage`（TItem.cs:858），否则用 ꢒ.ꞇ 生成字形位图缓存后画（TItem.cs:690）。
- **整串模式**（`isLongStr == true`）：`TItem.ꞇ()` 无参（TItem.cs:1220）走 `ꢒ.ꞇ(..., posX, posY, 0,0,0,0, A_10:true, A_11:false)` 后整块贴图（TItem.cs:1333-1336）；`TItem.ꞇ(Graphics)`（TItem.cs:1381）走 `A_0.DrawImage(_꧶._A839[key], posX, posY)`（TItem.cs:1518）。

坐标：**`posX/posY` 是绝对屏幕像素**（480×320 或 320×480），不是相对 group 的偏移（见 §6）。

颜色：文字颜色 = `FontConfig.color`（唯一来源）。`ThemeConfig.barFrontColor/barBackColor` 只用于状态条（StatuBar.cs:670-671）。

另外整屏还有一处 `DrawString`：`ScreenTip`（提示条），`graphics.DrawString(current.content, font, solidBrush, new Rectangle(posX,posY,W,H), stringFormat)`（**꧶.cs:4270**），字体族用 `_꧶.ꢒ`、FontStyle.Bold，颜色 `current.color`。

## 4. 是否存在"字体渲染 vs 精灵图渲染"两种模式

**结论：TItem 文字只有一种机制——字体渲染（DrawString）。** 不存在按 item 切换的"精灵图/点阵字库"文字模式。

代码证据：
- `flashDataOffset`（被认为是"精灵图偏移"的字段）全工程无任何读取（仅 TItem.cs 声明）。
- TItem 的三个绘制方法（`대()`、`ꞇ()`、`ꞇ(Graphics)`、`ꞇ(int,int)`）最终全部经 `ꢒ.ꞇ(...)` → `Graphics.DrawString`。没有"从字节数组拷贝像素"的文字分支。
- 真正用像素缓冲（"flash data"）的只有**状态条和弧形条**：
  - `StatuBar.frontData/backData/backFullData/backImgData`（StatuBar.cs:298-484，写入于 `_A7E0` 用 `ꢒ._A839(bitmap)` 转像素数组，StatuBar.cs:843/1092），`갌()` 用 `ꢒ.ꞇ(backData, length-curLen)`+`ꪨ.ꭚ.ꪨ(...)` 贴图（StatuBar.cs:1171-1177）。
  - `ArchBar.archData/dataLen/dataLenArray`（ArchBar.cs:797-940，`긢()` 里 `Array.Copy(archData, ...)`，ArchBar.cs:1188/1298），`껔()` 用 `graphics.DrawArc` 逐度绘制（ArchBar.cs:1379-1380，꧶.cs:4136）。
  - `ThemeConfig.needRereshArch` 决定是否重建 arch 缓冲（ThemeConfig.cs:1557、1634）。

前端相关的开关字段真正作用（**选哪张整屏静态背景位图**，不切换文字机制）：
- `_꧶.ꢒ(bool A_0)`（꧶.cs:3981）：`if (A_0)` → 画 `osdWithFontBack`（꧶.cs:4085），否则画 `osdImg`（꧶.cs:4060）。
- 该 bool 来源于 `ThemeConfig.useOsdWithFontBack`（c.cs:10622/2279 把 `useOsdWithFontBack` 传入）。
- `enbaleOsdWithFontBack` 只是设置界面的可用性开关（c.cs:10508、f.cs:5648），并**不**决定渲染分支。
- `ThemeConfig.osdWithFontBack` 是可选的全屏"文字底图"；为 null 时该分支画不出来（꧶.cs:4069 判空），实际渲染退回 `osdImg`。

### "哪种模式才能渲染任意文字" → **两者都能；"任意文字"靠的是给 TItem 加大 `isLongStr=true` + `valueStr`**

- 想让一段任意文字上屏：加一个（或改一个）`TItem`，`enabled=true`、`isLongStr=true`、`strLen` 随意、`fontType` 非 null、`valueStr=你想要的文本`。它会在 `TItem.ꞇ()`/`ꢒ(bool)` 阶段被整串 `DrawString`。
- 现有主题里已经有这种 item 的（`Date / Weather / userDefine1..18`，都是 `isLongStr=true`）——它们本身就能显示任意串（userDefineN 的 valueStr 就是字面文本，见下）。
- **37 个主题全部属于"字体渲染"模式**（每个主题都有大量 enabled 且带 FontConfig 的 TItem；见第 9 节表）。没有纯精灵图主题。
- 判定：`enabledFontItems>0` → 字体模式。`dump-all` 实测 36 个主题有；另一个（`A EVA UI 002` 等）也>0。**37/37 全部为字体渲染**（`dump-all` 把 36 个含 group 项的主题归为 FONT，`AppConfig.data` 不是主题；实际 config 目录主题文件 37 个，另有 `科技横屏主题.data` 也是 FONT）。

**RamValue vs RamLoad**：
- `RamValue` = 内存已用绝对量（MB，5 位，左补 x）。
- `RamLoad` = 内存占用百分比（2 位，左补 x）。
两者是**不同 item，各自独立**，都要 data 里有对应 item 才会显示。

**InternetUp/InternetDown vs UPSPEED/DOWNDSPEED**：**无对应关系。** 主题 itemName 用 `InternetUp/InternetDown`（MB/s 上传/下载，见上表）；`UPSPEED/DOWNDSPEED` 只存在于 M_Data 注册表（M_Data.cs:3042-3043），不用于主题渲染。

补充：`_꧶.쉌()`（AdaptSensorData）遍历 `groupList` 的所有 item（꧶.cs:6094-6106），未匹配到任何名字的 item（如 userDefine/Date/Weather/GpuPower 之外的未知名字）不会报错，只是 valueStr 不变。

| `useOsdWithFontBack` | 可 false | **真正**决定画 osdWithFontBack 还是 osdImg（c.cs:10622→꧶.ꢒ(bool)） |
| `needRereshArch` | 可 false | 是否重建 arch 像素缓冲（ThemeConfig.cs:1557/1634） |
| `name` | 可 null（但建议） | 显示名；注意**启动选择用文件名（去扩展名），不是这个 name**（见 §7） |
| `userInfoCnt` | 可 0 | 自定义信息条数 |
| `barType` | 可 0 | 0/1 两种状态条底色模式（StatuBar.cs:733、c.cs:1416/1434） |

| `barFrontColor`/`barBackColor` | 可默认 | 状态条前/底色（StatuBar.cs:670-671，꧶.cs 未用于文字） |

**TGroup**（TGroup.cs:10）：
- `enabled`（默认 true，TGroup.cs:323）
- `groupName`——渲染**完全不用**做逻辑分支，仅分类/设置界面用。真正参与判定的 groupName：`"Gpu"/"Cpu"/"Ram"`（f.cs 预览逻辑 5687/5814/1659/1675）。
- `backImg`——TGroup 自带底图（TGroup.cs:133），渲染主循环**没用到**（未在 ꧶.늧/꧶.ꢒ 中引用）。
- `baseX`/`baseY`——**全工程无读取**（TGroup.cs 只有 getter/setter）。**TItem 的 posX/posY 是绝对屏幕坐标，不是相对 baseX/baseY。**
- `itemList`——该组条目；逐帧两遍：先 `_A839(int)`（写/更新像素缓冲，TGroup.cs:328），再 `ꦝ()`（画到屏幕，TGroup.cs:400）。

## 7. 主题选择机制

路径拼接（静态构造，**꧶.cs:6789-6791**）：
- `_꧶.ꥄ = Application.StartupPath + "\\config\\"` —— 主题目录
- `_꧶.ꦝ = _꧶.ꥄ + "statusbar\\"` —— 状态条底图目录
- `_꧶._꧶ = Application.StartupPath + "\\code.ini"`
- `AppConfig.data` 全路径 = `_꧶.ꥄ + "AppConfig.data"`（**꧶.cs:6719/6751**）

加载 AppConfig：`ꥄ.ꞇ(path)` 反序列化（**꧶.cs:6673**），失败/缺失则 `new AppConfig { themeIndex=0, deviceIndex=1 }`（꧶.cs:6707-6711、6636-6640、2971-2975）。保存：`ꥄ.ꞇ(path, _AA4F)`（꧶.cs:6751）。

主题列表构建（c.cs:10948）：`Directory.GetFiles(_꧶.ꥄ, "*.data")`，排除文件名为 `"AppConfig"` 的（c.cs:10886），每项生成 `new PreviewTheme(fileNameWithoutExtension, fullPath)`（c.cs:10894）。

决定用哪个主题（c.cs:12036-12239，themeList 初始化）：
1. 若 `AppConfig.themeName` 非空 → 遍历列表，`previewTheme2.name == _AA4F.themeName` 命中后 `m_똡.SelectedIndex = num11`（**c.cs:12049 / 12182**）。
2. 否则若 `AppConfig.themeIndex >= 0` → `m_똡.SelectedIndex = _AA4F.themeIndex`（**c.cs:12221 / 12239**）。

选中的主题：`ThemeConfig.ꞇ(previewTheme.path)`（c.cs:10574/12389/16845），随后 `new _꧶(themeConfig)`。

**让新主题成为默认主题的方法**：把新主题 `.data` 放 `patched\config\`，然后改 `patched\config\AppConfig.data`：
- 首选 `themeName = <文件名去扩展名>`（如 `科技横屏主题`），这是**按文件名匹配**的，最稳。
- 或设 `themeIndex`（列表排序后下标，GetFiles 顺序，不稳定，不推荐）。
- 对应 `deviceIndex`、`isLanscape` 要与主题匹配（否则分辨率/引脚错）。
当前实测 AppConfig：`themeIndex=25, themeName='科技横屏主题', deviceIndex=1, rotation=0`（`tools\theme\AppDump.exe` 输出）。

## 8. 序列化方法与用真实类型构造的可行性

写：`ThemeConfig._A839(string path)`（**ThemeConfig.cs:1316-1336**）→ 先 `긢()`（重置每个 item 的 `lastValueStr`，ThemeConfig.cs:991-1117），再 `ꥄ.ꞇ(path, this)`。
`ꥄ.ꞇ(string,object)`（**ꥄ.cs:222-310**）：`byte[] b = ꞇ(obj)` → `File.Create(path)` + `BinaryWriter.Write(b)`。`ꥄ.ꞇ(object)`（**ꥄ.cs:10-50**）= `BinaryFormatter.Serialize`。

读：`ThemeConfig.ꞇ(string path)`（**ThemeConfig.cs:1338-1364**）→ `(ThemeConfig)ꥄ.ꞇ(path)`；`ꥄ.ꞇ(string)`（ꥄ.cs:139-220）读字节→`ꥄ.ꞇ(byte[])`（ꥄ.cs:52）= `BinaryFormatter.Deserialize`。

**用真实 `usb_hid.ThemeConfig` 类型构造并序列化：可行。** 已用 `tools\theme\ThemeTool.exe` 实测：
- `roundtrip`：load→save→load，字段全等，且 `ThemeConfig.ꞇ(path)` 读回成功。
- `mk`：从零 `Activator.CreateInstance` 构造 `ThemeConfig/TGroup/TItem/FontConfig`、灌入 480×320 Bitmap、序列化、再读回（`groups=1 items=3`），`ThemeConfig.ꞇ(path)` 校验通过。
类型可见性：`usb_hid.ThemeConfig/TGroup/TItem/FontConfig/ArchBar/StatuBar/ScreenTip` 全部 **public + [Serializable]**（各自文件头 `public class`）。可通过反射（`Assembly.LoadFrom(exe)` + `GetType("usb_hid.ThemeConfig")`）直接使用；也可直接 `csc /r:UsbMonitor.exe` 强类型引用。

注意：`.data` 头部是标准 BinaryFormatter，程序集名写死 `usb_hid, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null`（hexdump 已确认）。用 patched 或原版 exe 的**同一版**类型序列化，程序都能读回。反序列化会触发 `Bitmap` 序列化，GDI+ 重新编码内嵌 PNG（gAMA/pHYs 块会变），所以 **round-trip 不是字节级完全相同，但字段与位图内容一致、程序能原样读回**（实测差异仅 6 字节，位于某内嵌 PNG 的 gAMA/pHYs）。

最小可用样板（工具里 `mk` 用的就是这套，见 `tools\theme\ThemeTool.cs` Make/MakeItem）：
```csharp
// 需要引用真实程序集；若用反射见 Tool 源码
object tc  = new ThemeConfig();          // tipList/groupList/barList 已 new
tc.isLanscape = true;  tc.deviceIndex = 1;  tc.name = "AutoGen";
tc.userInfoCnt = 1;  tc.barType = 0;  tc.needRereshArch = false;
var back = new Bitmap(480,320); back.SetResolution(72f,72f);
using (var g = Graphics.FromImage(back)) g.Clear(Color.Black);
tc.backImg = back; tc.osdImg = new Bitmap(back); tc.osdWithFontBack = new Bitmap(back);
tc.useOsdWithFontBack = true; tc.enbaleOsdWithFontBack = true;

var font = new FontConfig {
    name="40", size=40, color=Color.White,
    offsetX=11, offsetY=17, W=22, H=28, interval=22 };

var grp = new TGroup("AutoGroup");
grp.itemList.Add(new TItem("CPU温度","CpuTemp", 2, 40, 40, font, 0));      // intervalAll=0
grp.itemList.Add(new TItem("时间","Time",     5, 40,160, font, 0));
grp.itemList.Add(new TItem("自定义","userDefine1", 0, 40,220, font, 0, true, "HELLO")); // isLongStr=true, 任意串
tc.groupList.Add(grp);

tc._A839(@"...\config\新主题.data");   // 内部走 BinaryFormatter
// 读取: var t = ThemeConfig.ꞇ(@"...\config\新主题.data");
```
要点：`TItem` 构造会 `fontType = A_5.ꪨ()`（克隆）；`isLongStr=true` 才能显示任意长文本；`enabled` 构造默认 true。

## 9. 主题盘点（`dump-all patched\config` 实测）
